sha.env</code> — Persistent env vars (also editable via <code>akasha config env set</code>).</li>
            <li><code>connectors.env</code> — Telegram, Slack, Discord activation (see <a href="#channels">Channels</a>).</li>
            <li><code>agent_profile.json</code> — Agent profile: name, role, personality, rules, optional <strong>formality</strong> (formal / informal). Editable in Settings → Agent profile (web UI) or by editing the file and restarting the daemon.</li>
            <li><code>autonomous_mission.yaml</code> — Optional <strong>autonomous mission</strong> (objective, heartbeat, report directory). Editable in the Mission tab or via <code>/api/autonomous-mission</code>.</li>
            <li><code>voice_router.yaml</code> — Optional TTS/STT URLs (voice button in the web UI when STT is configured).</li>
          </ul>

          <h2>LLM router (<code>llm_router.yaml</code>)</h2>
          <p><strong>Location:</strong> <code>data_dir/llm_router.yaml</code> (or project root if missing from data_dir). <strong>Used by:</strong> daemon, <code>akasha config models …</code>. API keys can be <code>vault://key_name</code> or standard env vars (e.g. <code>OPENAI_API_KEY</code>).</p>

          <div class="callout callout-tip" style="margin: 1.25rem 0;">
            <span class="callout-icon">📌</span>
            <div class="callout-body">
              <strong><code>task_types</code></strong> is the main knob: each entry is <code>task_types.&lt;name&gt;: { primary, fallback, constraints? }</code>. The router picks a <strong>task type name</strong> from classification, system prompts, orchestration, or tool context, then loads the matching route. Define a <strong>primary</strong> (<code>provider</code> + <code>model</code>) and optional <strong>fallback</strong> chain for every behaviour you care about.
            </div>
          </div>
