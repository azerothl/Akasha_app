        <article class="docs-article" id="hermes-worktree">
          <h2>Git worktree (happy path)</h2>
          <p>Akasha exposes Git worktrees for parallel agent sessions without cloning twice. Typical operator flow:</p>
          <ol>
            <li><strong>List</strong> — <code>akasha worktree list</code> shows linked worktrees under your data directory or configured repo.</li>
            <li><strong>Add</strong> — <code>akasha worktree add &lt;name&gt; [&lt;branch&gt;]</code> creates an isolated checkout for a feature or agent run.</li>
            <li><strong>Work</strong> — point Code Studio evolutions or chat sessions at the worktree path; keep <code>main</code>/<code>master</code> clean for merges.</li>
            <li><strong>Doctor</strong> — <code>akasha worktree doctor</code> reports stale paths, missing branches, or dirty state before removal.</li>
            <li><strong>Remove</strong> — <code>akasha worktree remove &lt;name&gt;</code> after merge or abandon (daemon refuses if worktree is dirty unless forced).</li>
          </ol>
          <p>Specification: <a href="https://github.com/azerothl/Akasha/blob/main/spec/dev/roadmap/reference-products-parity-matrix.md" target="_blank" rel="noopener">reference-products-parity-matrix.md</a> (Git worktree row). For IDE-style git inside Code Studio projects, use the <strong>Branches</strong> tab on a studio project instead.</p>
        </article>
